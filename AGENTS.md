# Инструкции для агентов

Этот репозиторий хранит только тестовые GitHub Releases TrustTunnel Flutter
Client. Он нужен для разработки и проверки того же флоу обновления, который
будет использовать официальные релизы: в тестовой сборке меняется только
репозиторий-источник. Сейчас целевая платформа — Windows; позже добавится
standalone macOS с DMG.

## Адреса и инструкции

- Репозиторий: `Kondrashov16/trusttunnel-flutter-client-updater-test`.
- [Тестовые релизы](https://github.com/Kondrashov16/trusttunnel-flutter-client-updater-test/releases).
- [Официальные релизы и эталон формата](https://github.com/TrustTunnel/TrustTunnelFlutterClient/releases).
- Control center: `/Users/kondrashov/Documents/work/adguard/trusttunnel-flutter-client-control-center`.
  Публикация описана в `docs/updater-test-releases.md`, проверка Windows —
  в `testing-instructions/windows-updater.md`. Прочитай нужную инструкцию
  перед публикацией или тестированием; при отсутствии локальной копии используй
  [control center на GitHub](https://github.com/Kondrashov16/trusttunnel-flutter-client-control-center).

## Правила работы

- По умолчанию репозиторий приватный. Пользователь открывает его только на время
  проверки обновления и затем закрывает. Не меняй видимость без прямого поручения
  пользователя. В клиент не добавляются GitHub-токены или отдельный способ
  авторизации: проверяется обычный публичный флоу скачивания.
- Здесь нет исходников приложения или сборочного CI. Бинарники загружай только
  как assets GitHub Release; не коммить EXE, DMG, ZIP сборок, секреты и VPN-профили.
  Всё в git и в релизах должно быть пригодно для временного публичного доступа.
- Не меняй основной `TrustTunnelFlutterClient` без отдельной задачи. Для сборки
  используй существующие инструкции control center и выделенные сборочные копии.
- Перед работой проверь `git status --short --branch`, remote, существующие теги
  и релизы. Всегда указывай полный `--repo` в `gh`, чтобы не опубликовать тестовую
  сборку в официальном репозитории. На этой машине shell-команды запускай через
  `rtk`, произвольные команды — через `rtk proxy`.
- Для обычного latest-сценария: тег `vX.Y.Z`, имя `TrustTunnel vX.Y.Z`,
  опубликованный release без prerelease, явно выбранный Latest. Числовая версия
  должна совпадать с реальной версией приложения; не переименовывай старый EXE
  ради имитации новой версии. Тег указывает на коммит этого репозитория,
  исходный commit приложения записывается в release notes.
- На 2026-10-19 Windows assets в официальных релизах ещё нет. Рабочая заготовка
  для Windows — один asset `TrustTunnelSetup.exe` из текущего Inno Setup.
  Перед будущей публикацией сверяй формат с официальным релизом и updater клиента;
  обновляй инструкцию control center при появлении окончательного контракта.
- Сначала подготовь draft с полным набором assets и описанием, затем публикуй.
  Не заменяй опубликованный бинарник и не переназначай старые теги; для новой
  сборки используй новую согласованную версию. Существующие пробные релизы
  не исправляй и не удаляй без поручения.
- Не пиши тесты без прямого указания.
